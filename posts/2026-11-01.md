## 解决“网络”问题

在国内的服务器上，直接装 Docker 会极其缓慢甚至报错（连不上官方源）。所以我们先配置一下国内的镜像源，然后再安装。

1. 更新软件包并安装依赖
~~~bash
apt update
apt install -y ca-certificates curl gnupg
~~~
2. 添加 Docker 的官方 GPG 密钥
~~~bash
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
~~~
3. 添加阿里云的 Docker 软件源
~~~bash
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://mirrors.aliyun.com/docker-ce/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  tee /etc/apt/sources.list.d/docker.list > /dev/null
~~~
4. 更新源并安装 Docker
~~~bash
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
~~~
5. 验证安装是否成功
~~~bash
docker run hello-world
~~~
- 如果看到 Hello from Docker! 字样：恭喜你，Docker 已经完美运行！
- 如果报错 Cannot connect to the Docker daemon：说明服务没启动，运行 systemctl start docker 并 systemctl enable docker 即可。

## 配置 Docker 镜像加速器
`docker run hello-world`能成功，说明你拉取了官方镜像。但国内如果不配加速器，以后拉取大镜像（比如 MySQL、Nginx）可能会卡死。
我们直接写入国内常用的加速地址：
~~~bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<EOF
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me"
  ]
}
EOF
systemctl daemon-reload
systemctl restart docker
~~~

## 跑一个真实的应用测试(Nginx)

1. 拉取并后台运行 Nginx 容器，把服务器的 80 端口映射到容器的 80 端口：
~~~ bash
docker run -d --name my-nginx -p 80:80 nginx
~~~
1. 检查容器是否在运行
~~~bash
docker ps
~~~
预期结果：你会看到一个叫 my-nginx 的容器，状态显示 Up（运行中），并且在 PORTS 那一列显示 0.0.0.0:80->80/tcp。
1. 放行防火墙的 80 端口
因为我们的 UFW 防火墙目前只开了 22 端口，80 端口是拒绝外部访问的。请在服务器里执行：
~~~bash
ufw allow 80/tcp
~~~
1. 浏览器访问测试
打开你电脑上的浏览器，输入你的域名或公网 IP。
如果你能看到网页上写着大大的 "Welcome to nginx!"，就说明你的第一个 Docker 应用完美运行了！

## 问题：文件在哪里
**核心概念：Docker 的容器（Container）内部是一个完全隔离的微型系统。**
当你执行 `docker run nginx` 时，Docker 并没有把 Nginx 的文件散落在你真实的服务器（宿主机）硬盘里，而是把它们打包在一个完全独立的小盒子里。
### 📦 第一层：容器内部的视角（假装你现在身处盒子里）
如果你“钻进”这个 Nginx 容器里看，它的文件结构和普通的 Linux 是一模一样的。

  - **配置文件**：在 `/etc/nginx/` 目录下（比如 `nginx.conf`）。

  - **网页文件（HTML）**：在 `/usr/share/nginx/html/` 目录下（那个 "Welcome to nginx!" 的页面就在这里）。

  - **日志文件**：在 `/var/log/nginx/` 目录下。
### 🖥️ 第二层：宿主机上的视角（站在你现在的服务器上看）
如果你的 Nginx 容器跑起来之后，你在宿主机上直接找，是找不到 `/etc/nginx` 这个目录的。

那这些文件在物理硬盘的哪呢？
答案是：在 `/var/lib/docker/` 目录下。
Docker 会在那个目录里生成一堆由长串乱码命名的文件夹（比如 overlay2），你的 Nginx 镜像层和容器里产生的新文件，都被存在那里。
> ⚠️ 极其重要的警告：
> **千万不要去 `/var/lib/docker/` 里面手动修改文件！** 那里是 Docker 的私有领地，直接改会导致容器崩溃或数据损坏。
### 🛠️ 动手实践：怎么进入容器里面看看？
既然你看不到，Docker 提供了一个“穿墙”命令，让你直接进入容器内部。
~~~bash
docker exec -it my-nginx /bin/bash
~~~
- `exec`：代表在运行的容器里执行命令。

- `-it`：给你分配一个交互式的终端。

- `my-nginx`：你的容器名字。

- `/bin/bash`：你要运行的命令（就是给我个 Shell 界面）。

进去之后，你会发现命令提示符变了（类似 root@a1b2c3d4...:/#）。 此时，你输入：

~~~bash
ls /usr/share/nginx/html/
~~~
你就能看到 index.html 和 50x.html 了。甚至你可以用 cat /usr/share/nginx/html/index.html 看到网页的源码。

看完之后，输入 exit 按回车，你就退回到你的宿主机（dev01）了。

### 🚨 灵魂拷问：如果你想修改网页内容怎么办？

如果你用上面的方法进去，用 `vi` 改了网页内容，**你一旦把这个容器删了，你改的东西就灰飞烟灭了**。

这就是 Docker 的另一个核心概念：**数据卷（Volume）或目录映射（Bind Mount）**。

如果你想让容器里的网页，对应到你真实服务器上的文件，比如 `/root/my-website`。你应该在第一次启动容器的时候，加上 `-v` 参数：

~~~bash
# 假设你在宿主机建了 /root/my-website 目录，放了你自己的 index.html
docker run -d --name my-nginx -p 80:80 -v /root/my-website:/usr/share/nginx/html nginx
~~~

这行命令的意思是：**把宿主机的 `/root/my-website` 目录，映射（覆盖）到容器里的 `/usr/share/nginx/html` 目录**。
这样，你在宿主机改文件，网页立马生效，而且删了容器，你的文件还在宿主机上。
