# uv 的使用

## 背景

在学习一个 Python 开源项目时，遇到了需要把本地环境与服务器环境对齐的问题。项目作者使用 uv 管理依赖，因此顺便把 uv 的基本用法和这次的踩坑过程记录下来。

## uv 是什么

uv 是 Astral 公司（也是 Ruff 的开发者）用 Rust 编写的 Python 包管理器，可以替代 pip、venv、pip-tools 等工具。官方宣称速度比 pip 快 10–100 倍。核心价值是**依赖版本锁定**和**可复现环境**。

## 安装

**Windows（PowerShell）**

~~~powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
~~~

**Linux（服务器）**

~~~bash
curl -LsSf https://astral.sh/uv/install.sh | sh
~~~

安装后需要让 PATH 生效。Windows 下重开终端或手动刷新：

~~~powershell
$env:Path = "$env:USERPROFILE\.local\bin;$env:Path"
~~~

Linux 下：

~~~bash
source $HOME/.local/bin/env
~~~

如果希望长期生效，把上面这行加入 `~/.bashrc`。

## 核心命令

### 同步依赖

~~~bash
uv sync
~~~

根据 `uv.lock` 安装依赖，创建或更新 `.venv` 虚拟环境。

**注意**：默认只安装运行时依赖，不包含开发工具（pytest、ruff、mypy 等）。如果项目把开发工具放在 dev 依赖组里，需要：

~~~bash
uv sync --all-extras
# 或
uv sync --dev
~~~

### 运行代码

~~~bash
uv run python -m 模块路径
uv run pytest
uv run ruff check .
~~~

`uv run` 会自动检查环境是否和锁文件一致，需要时自动同步，不需要手动激活虚拟环境。

### 添加依赖

~~~bash
uv add requests
~~~

同时更新 `pyproject.toml` 和 `uv.lock`。**`uv.lock` 必须提交到版本控制**，否则失去环境对齐的意义。

## 本次踩坑记录

### 1. 相对导入报错

~~~text
ImportError: attempted relative import with no known parent package
~~~

**原因**：直接 `python 文件路径` 运行带相对导入（`from .art import ...`）的模块，Python 不知道父包是谁。

**解决**：用 `-m` 以模块方式运行：

~~~bash
uv run python -m src.hyperskill_python_portfolio.zookeeper.main
~~~

在 PyCharm 中，需要把运行配置的目标类型从 "Script path" 改为 "Module name"，填入完整模块路径。

### 2. GitHub 克隆超时

~~~text
fatal: unable to access 'https://github.com/...': GnuTLS recv error (-110)
~~~

**原因**：服务器直连 GitHub 时 TLS 连接被中断，国际线路问题。

**解决**：使用镜像站：

~~~bash
git clone https://ghproxy.net/https://github.com/rabestro/hyperskill-python-portfolio
~~~

或使用浅克隆减少传输量：

~~~bash
git clone --depth 1 <仓库地址>
~~~

### 3. 服务器下载慢，关终端中断

`uv sync` 在前台运行时，关闭 SSH 终端会中断下载。已下载完成的包会留在 `~/.cache/uv` 缓存中，下次重试可复用；未下载完的包需要重新下载（uv 不支持断点续传）。

**解决**：用 `nohup` 放后台：

~~~bash
nohup uv sync --all-extras > uv_sync.log 2>&1 &
tail -f uv_sync.log
~~~

或用 `screen`：

~~~bash
screen -S uvsync
uv sync --all-extras
# Ctrl+A 然后 D 暂时离开
# 下次 screen -r uvsync 恢复
~~~

### 4. `pytest` / `ruff` 找不到

~~~text
error: Failed to spawn: pytest
~~~

**原因**：`uv sync` 默认不安装 dev 依赖组。

**解决**：`uv sync --all-extras`。

## 服务器验证流程

克隆项目后，在服务器上只做"验证"，不做"读代码/改代码"：

~~~bash
cd 项目目录
uv sync --all-extras
uv run pytest          # 看测试是否全绿
uv run ruff check .    # 看 lint 是否通过
uv run python -m 模块路径   # 跑一个交互程序确认能启动
~~~

这三步验证的是：`uv.lock` 能否在 Linux 上复现出和本地一致的环境，代码行为是否跨平台一致。

## 小结

- uv 的核心价值是**锁文件 + 可复现环境**，适合有本地/服务器对齐需求的场景。
- 日常只需掌握 `uv sync`、`uv run`、`uv add` 三个命令。
- 带相对导入的模块必须用 `-m` 运行。
- 服务器上长时间下载用 `nohup` 或 `screen` 放后台。
- `uv sync` 默认不装 dev 依赖，需要 `--all-extras`。
